A semantic layer your agents can actually use

July 2026 · draft — working notes; the argument is stable, the prose isn't.

Every text-to-SQL demo works. Almost none of them survive contact with a real enterprise warehouse. The gap isn't the model — it's that the warehouse doesn't mean anything.

A table called txn_f_v3 with 400 columns is perfectly legible to the five analysts who have been burned by it before. They know that amount is in cents before 2021 and dollars after, that status = 7 means "settled but disputed," and that the join to the customer dimension silently drops records from one acquisition. None of that knowledge is in the warehouse. It's in Slack threads, in old dashboards, and in people's heads. An agent pointed at the raw schema doesn't have access to any of it — so it writes confident, syntactically perfect, wrong SQL.

I spend my days on this problem. At American Express I lead knowledge-graph and semantic-layer work on Lumi, the enterprise data warehouse (it runs on BigQuery). Nights and weekends I've been building wyla, an open proof-of-concept of the same idea with none of the enterprise constraints. Both projects have pushed me to the same conclusion:

The unit of progress isn't a better model or a better prompt. It's turning tribal knowledge about data into a queryable artifact — a semantic layer — and serving it to agents as a first-class interface.

What "semantic layer for agents" actually means

Three properties, in increasing order of difficulty:

  1. Definitions live in one place. Metrics, dimensions, and join paths are declared once (LookML, dbt metrics, a graph — the syntax matters less than the discipline) instead of re-derived in every query. Humans have wanted this for twenty years; agents make it non-negotiable, because an agent will happily invent a definition if you don't hand it one.
  2. Provenance is typed, not vibes. When the layer answers "monthly active customers," it should also answer where that number comes from — which source system, which transformation, how fresh, how trusted. In wyla every node in the graph carries provenance as part of its type. This is what lets a downstream agent (or auditor) decide how much to believe.
  3. The interface is an agent protocol, not a BI tool. I serve the graph over MCP so any agent runtime can discover and query it as tools, with guardrails at the boundary: the agent gets a sandboxed analyst environment and governed query surface, not warehouse credentials. "Read-only access to meaning" is a much safer contract than "read-only access to tables."

What surprised me

The graph is more useful as a compiler target than as a database. I originally imagined agents traversing the knowledge graph directly. In practice the winning pattern is: agent asks a semantic question → the layer compiles it against the graph into governed SQL → results come back with provenance attached. The graph is the source of truth the compiler consults, not the thing the agent wanders around in.

Guardrails are a product feature, not a tax. The moment the agent could only act inside a sandbox with an explicit tool surface, the conversation with security and governance teams changed from "no" to "how fast." In an enterprise, the constraint is the product.

Most of the work is archaeology. Fusing five data sources in wyla, the hard part was never the plumbing — it was deciding which of three conflicting definitions of "customer" the graph should bless, and recording why. Building the semantic layer forces the organization to have arguments it has been deferring for years. That's the value, and it's also why it's slow.

Where this goes

Every company is about to discover that their data platform's real customer base just grew: it's analysts and agents now. The companies that treat agent-legibility as an architectural requirement — typed definitions, provenance, protocol-level access — will compound. The ones that bolt a chatbot onto an unmodeled warehouse will demo well and quietly ship wrong numbers. I'm betting my working hours on the first group, and some of my capital too.
