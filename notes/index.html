Serving a knowledge graph to agents over MCP

For wyla I needed agents to query a provenance-typed knowledge graph without handing them database credentials. MCP turned out to be the right seam: the graph exposes a small set of tools (search entities, expand relationships, compile a metric query), and any MCP-speaking runtime — Claude, or an agent built on Google's ADK — can discover them without custom integration.

The lesson that stuck: design the tool surface around questions, not tables. My first version exposed CRUD-ish graph operations and agents flailed. The second version exposed five verbs an analyst would recognize, and suddenly the same models looked smart. The intelligence was in the interface.

July 2026

Watching agents work in parallel changes how you delegate

I built ClaudeWatch, a small macOS app that monitors and dispatches multiple Claude Code sessions, because I kept losing track of which terminal was doing what. The surprise wasn't the tooling — it was behavioral. Once I could see all sessions at a glance, I started scoping tasks smaller and more independently, the way you would for a team. Observability didn't just monitor the work; it restructured it.

July 2026

Most agent frameworks are 90% ceremony

After building agents with several frameworks, I wrote liteagent to test a hunch: the useful core of an "agent" is a loop, a tool registry, and a termination condition — three lines of intent buried under thirty of boilerplate. Rebuilding the minimum yourself once is the fastest way to evaluate every framework afterward: you can finally see which abstractions pay rent.
